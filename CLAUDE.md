# gym-tracker

Vite + React + TypeScript. Tailwind v4 for styling, shadcn for UI primitives, Supabase for auth and data.

## Commands

| Command          | What it does                         |
| ---------------- | ------------------------------------ |
| `npm run dev`    | Dev server on :5173                  |
| `npm run build`  | Typecheck (`tsc -b`) then Vite build |
| `npm run lint`   | oxlint                               |
| `npm run format` | Prettier over the repo               |

Run `format`, `build` and `lint` before committing.

## Component convention

**One component per file.** A file exports exactly one component, as its default export. The filename is the kebab-case version of the component name — `check-inbox.tsx` exports `CheckInbox`.

**A component with private sub-components becomes a folder.** The folder is named after the component, and holds the component's own file plus everything only it uses:

```
src/components/
  gym-dashboard/
    gym-dashboard.tsx     ← the component the folder is named for
    home-screen.tsx       ← only used by gym-dashboard
    workout-screen.tsx
    progress-screen.tsx
    history-screen.tsx
    profile-screen.tsx
    stat.tsx              ← shared by home-screen and progress-screen
    demo-data.ts          ← hardcoded placeholder data
  auth-screen/
    auth-screen.tsx
    check-inbox.tsx
    logo.tsx  ✗           ← don't: logo is used outside auth-screen
```

No `index.tsx` re-exports — import the real path (`@/components/gym-dashboard/gym-dashboard`) so the file you import matches the file you open.

**Once something is used by two different features, it moves up to `src/components/`.** `logo.tsx` started inside `auth-screen/` and moved out when the dashboard header needed it too.

**`src/components/ui/` is shadcn's territory.** Generated by `npx shadcn@latest add <name>`. Edit these freely — they're our source now — but expect the CLI to overwrite them if the same component is re-added.

## Styling

Tailwind utilities in `className`. No CSS files beyond `src/index.css`.

Colours are semantic tokens (`bg-background`, `text-muted-foreground`, `bg-accent`), defined as CSS variables in `src/index.css`. Never hardcode a palette colour like `bg-neutral-900` — use a token so the theme stays swappable.

Use `cn()` from `@/lib/utils` whenever classes are conditional or arrive via props. It merges conflicts so a caller's `className` reliably beats a component's defaults. Watch out: responsive variants only override matching variants, so `text-xs` does not beat a base `md:text-sm` — you need `md:text-xs` too.

## Supabase

- Client in `src/lib/supabase.ts`, session state in `src/lib/use-session.ts`.
- `src/App.tsx` gates on session: no config → `MissingConfig`, no session → `AuthScreen`, otherwise the dashboard.
- Config comes from `.env.local` (gitignored): `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`.

**Env vars are inlined at build time.** Vite folds `import.meta.env` into constants, so a build without them dead-code-eliminates whole branches — the app silently shrinks to just the `MissingConfig` screen. If a deploy renders "Supabase not configured", the env vars were missing at build, and setting them requires a rebuild. Vercel needs both vars set for production.

## Code style

- No comments unless genuinely necessary — let the code read for itself.
- Single quotes, no semicolons, 100 char width (Prettier enforces it).
- Import order: React, third-party, then `@/` paths.
